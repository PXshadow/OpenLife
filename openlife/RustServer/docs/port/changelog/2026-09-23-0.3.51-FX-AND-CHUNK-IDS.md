# 0.3.51 — own food updates, and no dummy ids on the original client

Haxe `sendFoodUpdate` goes only to that player's connection. The official client writes every `FX` onto the local food bar and move speed, so a nearby AI eat or use was replacing your food and health with theirs.

Map chunks and map changes for the original client no longer contain synthetic multi-use ids. Those ids are not in its object bank, and `getObject(id)->isStatue` crashes while a new area is applied. The parent object id is sent instead. Open Life clients still get the raw id.
