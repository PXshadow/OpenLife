# 0.3.53 — multi-use state stays the dummy id

Haxe `ObjectHelper.dummyId` is what a map cell stores. Full uses keep the parent id. Fewer uses are `dummyObjects[numberOfUses - 1].id`, allocated after the last real object. The client builds that same id list, so the id is the use sprite.

`mapIdToVanillaId` does not replace a dummy with its parent. With `lastVanillaID < 1` the id is sent unchanged. With the cutoff set, an id above `lastOpenLifeID` is shifted by `lastOpenLifeID - lastVanillaID` into the vanilla client's dummy range.

0.3.51 was rewriting those ids to the parent and dropping the use count. This build sends the dummy id again.
