# Server movement feedback (headless client probe)

Date: auto-generated by `ohol-headless --probe-move`

## Summary

Logged into the local OpenLifeReborn game port (`127.0.0.1:8005`) with a real account and sent an original-format `MOVE` path. The server **did not fully return** the movement responses expected by the official OHOL protocol / client.

## Expected (protocol.txt + LivingLifePage)

After client sends:

```text
MOVE xs ys @seq_num xdelt0 ydelt0 ...#
```

with `seq_num` starting at **2** for the first move of a life:

1. **`PM` (PLAYER_MOVES_START)** for that player:
   `p_id xs ys total_sec eta_sec trunc xdelt0 ydelt0 ...`
2. While walking, other PUs may arrive with `done_moving_seqNum == 0`.
3. On arrival, **`PU`** with `done_moving_seqNum == seq_num` (and force usually 0), stationary at destination.
4. On truncated/forced path: `force=1` PU + client replies `FORCE x y#` before further moves.

## Observed

| Check | Result |
|-------|--------|
| PM for our player after MOVE | YES |
| Any PM after MOVE | YES |
| PU done_moving matching seq 2 (or dest) | **NO** |

## Client wire (faithful)

- Framing: ASCII messages terminated by `#`
- MOVE exact spacing: `MOVE xs ys @seq d0x d0y ...#`
- Login: SN challenge + HMAC-SHA1(password) + HMAC-SHA1(pure account key)
- MC binary after `#` is skipped by compressed size (frame sync)

## Suggested server fixes

1. On accepted MOVE intent: broadcast **PM** to interest set (or all if broadcast_all_updates).
2. When timed path finishes: emit **PU** with `done_moving_seqNum` equal to client `@seq`.
3. On jump/truncation: PU `force=1` at corrected tile; ignore further pos-sensitive cmds until `FORCE x y#`.
4. Confirm MOVE is not dropped due to seq, start-tile mismatch, or ticket/session mapping.
